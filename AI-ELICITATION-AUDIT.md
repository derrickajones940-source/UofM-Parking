# AI Elicitation Audit

## What the AI Got Right

The AI correctly identified several important parts of the parking app. It included parking availability, the three parking statuses of Available, Getting Full, and Full, parking costs, parking restrictions, and walking distance. It also included parking alerts and user reports, which are part of the app concept.

The AI also correctly separated the requirements into user stories and non-functional requirements. The response gave the project a useful starting point for organizing the requirements.

## What the AI Missed

The AI did not ask for enough detail about how some of the requirements should work.

1. **Status changes:** The AI did not ask what specifically causes a parking lot to change from Available to Getting Full or from Getting Full to Full.

2. **Recent reports:** The AI mentioned recent parking reports but did not ask how long a report should be considered recent.

3. **Parking restrictions:** The AI included restrictions but did not ask how restrictions should affect the user's parking choices.

4. **Walking distance:** The AI included walking distance but did not ask how the walking distance should be calculated or what location on campus should be used as the destination.

These questions would need to be answered before development so the requirements are clear.

## What the AI Invented

The AI suggested or implied several features that were not part of the original app concept and are not currently wanted for the project.

Examples include:

* GPS or location tracking
* Map integration
* User accounts and authentication
* Payment processing
* License plate information
* Automatic parking sensors
* Administrator features

These features could make the project much larger and more complicated than intended. They should not be added unless the project scope is changed.

## What the AI Added That Was Useful

The AI helped identify some areas that were not clearly defined in the original concept. In particular, it introduced measurable requirements involving response time, automated testing, and data freshness.

These ideas can help make the project requirements easier to test. However, they should still be reviewed by the project team before being accepted.

## Overall Judgment

The AI was useful as a starting point, but its output could not be accepted without review. It correctly identified many of the main features of the parking app, but it did not ask enough questions about important details. It also included several features that were outside the intended project scope.

The final requirements should therefore be based on the project team's decisions rather than simply accepting everything produced by the AI.
